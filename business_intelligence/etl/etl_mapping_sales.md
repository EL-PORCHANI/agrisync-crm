# AgriSync AI - ETL Mapping for Sales Data Warehouse

## Objective

This document defines how operational CRM data is extracted, transformed, and loaded into the AgriSync AI Data Warehouse.

The goal is to prepare sales data for Power BI dashboards, including revenue analysis, product performance, client analysis, commercial activity, and zone-based reporting.

---

## Source System

The source system is the operational CRM database used by the AgriSync AI platform.

Main source entities:

- Clients
- Products
- Orders
- Order Lines
- Users
- Zones

---

## Target Data Warehouse Tables

The first Data Warehouse version uses a simplified sales star schema.

Target tables:

- dim_date
- dim_client
- dim_product
- dim_user
- dim_zone
- fact_sales

---

## Dimension Mapping

### dim_date

| Target Field | Source Field | Transformation Rule |
|---|---|---|
| date_key | orders.order_date | Convert date to YYYYMMDD integer |
| full_date | orders.order_date | Keep complete order date |
| day | orders.order_date | Extract day |
| month | orders.order_date | Extract month |
| quarter | orders.order_date | Calculate quarter from month |
| year | orders.order_date | Extract year |

---

### dim_client

| Target Field | Source Field | Transformation Rule |
|---|---|---|

## Fact Table Mapping

### fact_sales

| Target Field | Source Field | Transformation Rule |
|---|---|---|
| sales_key | Generated by Data Warehouse | Auto-increment surrogate key |
| date_key | orders.order_date | Match with dim_date.date_key |
| client_key | orders.client_id | Match with dim_client.client_id |
| product_key | order_lines.product_id | Match with dim_product.product_id |
| user_key | orders.user_id | Match with dim_user.user_id |
| zone_key | clients.zone_id | Match with dim_zone.zone_id |
| order_id | orders.id | Keep original CRM order ID |
| quantity | order_lines.quantity | Copy ordered quantity |
| unit_price | order_lines.unit_price | Copy unit price at order time |
| line_total | quantity * unit_price | Calculate sales line total |
| order_status | orders.status | Copy order status |

---

## Transformation Rules

The ETL process must apply the following rules:

1. Extract CRM data from operational tables.
2. Remove duplicate records.
3. Validate required fields such as client, product, quantity, and price.
4. Convert order dates into date dimension fields.
5. Generate surrogate keys for dimension tables.
6. Match fact records with dimension keys.
7. Calculate line_total using quantity and unit_price.
8. Load dimensions before loading fact_sales.
9. Refresh Power BI dashboards after loading the Data Warehouse.

---

## Loading Order

The correct loading order is:

1. dim_date
2. dim_client
3. dim_product
4. dim_user
5. dim_zone
6. fact_sales

This order is important because fact_sales depends on the dimension keys.

- Revenue by product

- Revenue by zone
- Orders by commercial user
- Quantity sold by product category
- Sales trend over time
- Top clients by revenue
- Top products by sales amount
